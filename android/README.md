# УПЭ Стоп для Android

Офлайн-помощник оператора при остановке технологической линии УПЭ. Реализует [ТЗ](../docs/android/TZ.md):

- чек-лист с отметками и временем выполнения;
- пошаговый режим «что делать сейчас»;
- таймеры этапов, которые работают при закрытом приложении и после перезагрузки;
- справочник с поиском по позициям, критические правила;
- тренажёр с историей попыток;
- журнал остановки с отправкой через «Поделиться».

Приложению не нужны интернет и сервер: разрешения `INTERNET` нет, все данные хранятся только на устройстве. Содержание алгоритма берётся из того же файла, что и в веб-версии: [`data/stop-algorithm.json`](../data/stop-algorithm.json).

## Где взять APK

- **Последняя версия из `main`:** https://github.com/Nodensss/OSTANOV/releases/latest — файл `upe-stop-<версия>.apk`. Ссылку можно открыть прямо на телефоне.
- **Сборка из PR:** вкладка *Checks* → workflow «Android APK» → *Summary* → *Artifacts*:
  - `upe-stop-apk` — APK;
  - `screenshots` — снимки всех экранов из UI-теста;
  - `reports` — отчёты lint и тестов.

Установка: открыть APK на телефоне и разрешить установку из этого источника. Если APK подписан debug-ключом CI, при обновлении может понадобиться удалить старую версию. Чтобы обновления ставились поверх, задайте секреты подписи (раздел 11 ТЗ).

## Сборка и проверки

Нужны JDK 17+, Android SDK (platform 35, build-tools 35.0.0) и Gradle 8.11.1. Всё это ставит `bash scripts/codex-android-setup.sh`. Gradle Wrapper не используется: исполняемые файлы обёртки бинарные. Для Android Studio лежит только `gradle/wrapper/gradle-wrapper.properties`, по нему Studio скачает нужный Gradle (File → Open → папка `android/`).

```bash
cd android
gradle --no-daemon testDebugUnitTest lintDebug assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
# Скриншоты экранов из UI-теста: app/build/screenshots/
python3 ../scripts/check-android-content.py   # тексты алгоритма не захардкожены в коде
```

## Архитектура

```text
app/src/main/java/ru/upestop/app/
├── UpeStopApp.kt        Application + AppContainer (ручной DI), общий поток StopSnapshot
├── MainActivity.kt      Compose, edge-to-edge, открытие этапа из уведомления
├── data/                модель JSON, загрузка и проверка алгоритма, Room, DataStore, репозитории
├── domain/              чистый Kotlin, покрыт тестами: TimerMath, Progress, PositionSearch,
│                        TrainerEngine, StopReportBuilder, AlgorithmValidator, TimeFormat
├── timer/               TimerController (БД + AlarmManager + уведомления), receivers
└── ui/                  Compose-экраны: home, checklist, step, reference, rules, trainer,
                         history, journal, settings; navigation; theme; components
```

- Каждый экран — ViewModel со `StateFlow` и Composable.
- Все изменения таймеров идут через `TimerController`, откуда бы они ни пришли: интерфейс, кнопка «Пауза» в уведомлении, будильник, перезагрузка. Поэтому состояние в БД, будильник и уведомление всегда совпадают.

Тесты (`app/src/test`, JVM):

- unit-тесты `domain/` и проверка настоящего `data/stop-algorithm.json`;
- `AppJourneyTest` на Robolectric проходит все экраны приложения и сохраняет скриншоты.

## Как обновлять данные

Править только `data/stop-algorithm.json` в корне репозитория: Android подключает его как assets, копии нет.

- Идентификаторы операций (например, `9.5`) не менять: по ним хранятся отметки.
- Если JSON не пройдёт проверку, приложение покажет экран с перечнем ошибок вместо алгоритма.
- `AlgorithmJsonTest` проверяет файл при каждой сборке.

## Принятые решения

1. **Gradle Wrapper без `gradlew` и `gradle-wrapper.jar`.** Бинарные файлы не коммитятся. CI использует `gradle/actions/setup-gradle` с версией 8.11.1, Android Studio — `gradle-wrapper.properties`.
2. **Длительность таймера фиксируется при запуске** — колонка `duration_ms` в `timer_state` сверх ТЗ. Переключение тестового режима не меняет уже идущий таймер.
3. **Звук и вибрация окончания таймера задаются системным каналом уведомлений** «Таймеры — завершены»: звук будильника и вибрация. На Android 8+ приложение не может менять звук канала после его создания, поэтому вместо двух переключателей из F-9 в настройках есть кнопка «Настроить» — она открывает настройки канала. Переключатель «Вибрация при отметке» управляет тактильным откликом при отметке операции. Если приложение открыто в момент окончания, сигнал подаёт то же уведомление (канал высокой важности звучит и на переднем плане).
4. **Сброс прогресса.** Кнопка «Журнал» в диалоге открывает экран журнала, где есть «Поделиться» и «Копировать». После возврата сброс запускается повторно из меню. Так проще, чем цепочка «поделиться → снова спросить».
5. **Пошаговый режим.** После «Выполнено» курсор сразу переходит к следующей неотмеченной операции, а «Этап N завершён» показывается в snackbar. Блок предупреждений раскрыт на первом шаге этапа и свёрнут на остальных.
6. **Поиск в справочнике** идёт по позициям, тексту и параметрам операций. Латиница, похожая на кириллицу (`a-401` → `А-401`), пробелы и дефисы нормализуются.
7. **Тренажёр.**
   - В списке наборов только этапы, у которых есть вопросы; у веб-версии пустые наборы — это баг.
   - Вопросы с `phaseId = null` вынесены в набор «Критические правила».
   - Кнопка «Начать» закреплена внизу экрана, потому что список наборов длинный.
   - Попытка сохраняется при старте, поэтому незавершённая видна в истории.
8. **Журнал остановки.** У идущего таймера кроме прошедшего времени указано и время запуска. Текст на экране переносится по словам, в «Поделиться» уходит без изменений.
9. **Разрешение на уведомления** запрашивается один раз при первом запуске на Android 13+. Дальше — плашка «Разрешить» у таймера и раздел «Разрешения» в настройках.
10. **Иконка** — `mipmap-anydpi/` вместо `mipmap-anydpi-v26/`: при `minSdk 26` суффикс лишний, lint предупреждает.
11. **UI-тест на Robolectric** — сверх ТЗ. Добавлены тестовые зависимости `robolectric 4.14.1` и `compose ui-test`. Эмулятора в CI нет, а этот тест проверяет запуск всех экранов и делает скриншоты для просмотра без телефона.
12. **Репозитории** `ProgressRepository`, `TimerRepository` и `TrainerRepository` лежат в одном файле `data/Repositories.kt`: каждый — тонкая обёртка над DAO.

## Наблюдения по данным

Ошибок в `data/stop-algorithm.json` валидатор не нашёл. Два расхождения веб-версии с данными (сам JSON не менялся):

- Поле `critical: true` у этапа 14 есть в JSON, но отсутствует в TS-типе `Phase` и в веб-интерфейсе не показывается. В Android оно выводится бейджем «Критично».
- Тренажёр веб-версии предлагает наборы «Только этап N» для этапов 8, 12 и 16, у которых нет вопросов, — такой набор пуст.
