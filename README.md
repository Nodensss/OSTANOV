# УПЭ Стоп

Интерактивный Next.js-инструмент для оператора-технолога: чек-лист остановки технологической линии УПЭ, справочный просмотр алгоритма и тренажёр по контрольным вопросам.

Данные алгоритма не зашиты в компоненты. Этапы, параметры, позиции, предупреждения, критические правила и вопросы берутся из `data/stop-algorithm.json`.

## Стек

- Next.js 14 App Router
- TypeScript
- Tailwind CSS
- Prisma
- Neon Postgres через `DATABASE_URL`
- Vercel

## Локальный запуск

```bash
npm install
cp .env.example .env
npm run prisma:generate
npm run prisma:push
npm run dev
```

В `.env` нужно указать PostgreSQL/Neon строку:

```bash
DATABASE_URL="postgresql://USER:PASSWORD@HOST:PORT/DATABASE?sslmode=require"
```

После запуска приложение доступно на `http://localhost:3000`.

## Режимы

- `/checklist` — выполнение чек-листа с сохранением отметок и таймерами этапов 9 и 10.
- `/view` — справочный просмотр всех этапов с поиском по позициям.
- `/view/critical-rules` — отдельный экран критических правил.
- `/trainer` — тренажёр с вопросами из JSON.
- `/trainer/history` — история попыток текущей сессии.

## Деплой на Vercel

1. Импортировать репозиторий в Vercel.
2. Добавить `DATABASE_URL` в Environment Variables.
3. Выполнить `npm run prisma:push` для выбранной базы или подключить миграционный шаг отдельно.
4. Задеплоить проект.

## Как обновлять алгоритм

Для добавления нового этапа, позиции, предупреждения или вопроса нужно отредактировать `data/stop-algorithm.json`.

Основные массивы:

- `phases` — этапы остановки и чек-листы.
- `criticalRules` — критические правила.
- `trainerQuestions` — вопросы тренажёра.

Идентификаторы чеков должны оставаться стабильными, например `9.5`, потому что по ним сохраняется прогресс в БД.
