## 2. Цель и контекст

**Пользователь** — оператор-технолог установки полиэтилена высокого давления (УПЭ, ТНХК). Во время остановки технологической линии он идёт по утверждённому алгоритму: 16 этапов, около сотни операций, контрольные параметры, таймеры циркуляции, критические правила.

**Цель** — нативное Android-приложение, которое:

1. ведёт оператора по алгоритму остановки: чек-лист с отметками и временем выполнения, пошаговый режим «что делать сейчас», таймеры этапов с уведомлениями;
2. работает **полностью офлайн**: на установке может не быть сети, приложению не нужен интернет и сервер;
3. служит справочником (поиск по позициям оборудования, критические правила) и тренажёром (контрольные вопросы с историей попыток);
4. формирует журнал остановки (что и когда отмечено) и позволяет им поделиться.

**Главный принцип (как в веб-версии):** приложение **не добавляет процедурных шагов**. Этапы, операции, параметры, позиции, предупреждения, схемы, правила и вопросы берутся только из `data/stop-algorithm.json`. Ни один текст алгоритма не должен быть захардкожен в Kotlin-коде или `strings.xml`. Количества (этапов, операций и т. д.) всегда вычисляются из данных.

## 4. Исходные данные

### 4.1. Формат `data/stop-algorithm.json`

Типы описаны в [`lib/algorithm.ts`](https://github.com/Nodensss/OSTANOV/blob/main/lib/algorithm.ts). Kotlin-модель должна их повторять:

```text
StopAlgorithm {
  title: String                      // "Алгоритм остановки технологической линии УПЭ"
  subtitle: String                   // "Полиэтилен высокого давления · УПЭ · ТНХК"
  sources: List<String>              // основания (распоряжения и т. п.)
  phases: List<Phase>
  criticalRules: List<CriticalRule>
  trainerQuestions: List<TrainerQuestion>
}
Phase {
  id: Int                            // 1..16, порядок выполнения
  section: String                    // группа этапов: "Подготовка", "Изоляция и разгрузка", ...
  title: String
  subtitle: String
  condition: String?                 // условие применимости, напр. "Только при остановке более 12 часов"
  critical: Boolean = false          // есть в JSON (этап 14), в TS-типе отсутствует — учитывать!
  checks: List<CheckItem>
  warnings: List<WarningItem>?       // { title, text }
  positions: List<String>            // позиции оборудования: "А-401", "14047", "PV-10603"
  timer: TimerSpec?                  // { minutes: Int, label: String }
  scheme: Scheme?                    // { title, lines: List<String> } — текстовая схема с псевдографикой
}
CheckItem { id: String /* "9.5" */, text: String, type: "check" | "param", param: String? }
CriticalRule { id: String, title: String, rule: String, consequence: String }
TrainerQuestion { id: String, phaseId: Int?, question: String, options: List<String>, correct: Int /* индекс в options */, explanation: String }
```

Текущий объём (для ориентира, **не хардкодить**): 16 этапов в 5 разделах, 97 операций, 144 позиции, 7 критических правил, 15 вопросов. Таймеры есть у этапов 9 (40 мин) и 10 (180 мин), схемы — у этапов 10 и 11, условие — у этапа 11, `critical: true` — у этапа 14. У одного вопроса `phaseId = null` (вопрос по критическим правилам).

### 4.2. Как JSON попадает в приложение

- JSON **не копируется** в `android/`. Gradle подключает каталог `<корень>/data` как дополнительный каталог assets (см. Приложение А): `assets.srcDir(rootProject.file("../data"))`. Так веб и Android всегда используют одну и ту же версию файла.
- Парсинг через `kotlinx.serialization` с `ignoreUnknownKeys = true`. Для `type` — enum с `@SerialName("check")`/`@SerialName("param")`.
- При старте JSON парсится и проверяется валидатором (раздел 10). При ошибке парсинга или валидации приложение не падает, а показывает экран ошибки с текстом проблемы.
- Идентификаторы операций (`"9.5"`) — стабильные ключи прогресса. Отметки для ID, которых больше нет в JSON, игнорируются и не учитываются в прогрессе.

### 5.4. Ограничения на файлы

Агент не всегда может закоммитить бинарные файлы, поэтому:

- Иконка приложения — adaptive icon только из векторных XML (`drawable/ic_launcher_foreground.xml`, `ic_launcher_background.xml`, `ic_launcher_monochrome.xml`, `mipmap-anydpi-v26/ic_launcher.xml` и `ic_launcher_round.xml`). Мотив: контур восьмиугольника (знак «стоп») цвета `#60A5FA` на фоне `#0A0D0F`, внутри — галочка.
- Шрифты системные: `FontFamily.Default` для текста, `FontFamily.Monospace` для номеров, ID, параметров и таймеров. Шрифты IBM Plex не встраивать.
- Исполняемую часть Gradle Wrapper (`gradlew`, `gradlew.bat`, `gradle-wrapper.jar`) не добавлять. Локально и в CI используется установленный `gradle` версии 8.11.1 (`gradle/actions/setup-gradle` с `gradle-version`). Добавить только текстовый `android/gradle/wrapper/gradle-wrapper.properties` (Приложение А): по нему Android Studio сама скачает нужный Gradle.

## 6. Функциональные требования

Навигация: нижняя панель `NavigationBar` из 4 пунктов: **Главная · Чек-лист · Справочник · Тренажёр**. Остальные экраны (Пошаговый режим, Критические правила, История, Настройки, Журнал) открываются из этих четырёх и имеют кнопку «Назад» в `TopAppBar`. Системная кнопка «Назад» работает везде.

### F-1. Главная

- Заголовок `title` и подзаголовок `subtitle` из JSON.
- Метрики из данных: этапов, операций, правил, вопросов.
- Карточка **«Текущая остановка»**:
  - прогресс «Выполнено N из M» и полоса прогресса;
  - текущий этап — этап первой неотмеченной операции: «Этап 5 · Разгрузка реактора до 170 МПа»;
  - запущенные таймеры с живым обратным отсчётом: «Этап 9 · 23:41»;
  - кнопка **«Продолжить»** — открывает Пошаговый режим на первой неотмеченной операции. Если ничего не отмечено, кнопка называется «Начать остановку», если всё отмечено — «Остановка завершена», и она открывает Журнал.
- Плитки-переходы: Чек-лист, Пошаговый режим, Справочник, Критические правила, Тренажёр.
- Внизу мелким текстом: «Вспомогательный инструмент. При расхождении руководствуйтесь утверждёнными документами» и ссылка на «Настройки и о приложении».

### F-2. Чек-лист

Повторяет [`ChecklistClient.tsx`](https://github.com/Nodensss/OSTANOV/blob/main/components/checklist/ChecklistClient.tsx), [`PhaseCard.tsx`](https://github.com/Nodensss/OSTANOV/blob/main/components/ui/PhaseCard.tsx) и [`CheckRow.tsx`](https://github.com/Nodensss/OSTANOV/blob/main/components/checklist/CheckRow.tsx).

- Сверху закреплены прогресс «N из M шагов» и полоса прогресса. Если есть запущенные таймеры, там же мини-плашка с ними (нажатие прокручивает к этапу).
- Этапы сгруппированы по `section` (заголовки разделов в порядке первого появления) и идут в `LazyColumn`.
- Карточка этапа (сворачиваемая):
  - крупный номер `01`…`16` моноширинным шрифтом; у выполненного этапа он зелёный (`safe`);
  - метка «Этап N · section», заголовок `title`;
  - `condition` (если есть) — янтарным цветом под заголовком;
  - для `critical: true` — красный бейдж «Критично»;
  - счётчик «x/y» отмеченных операций;
  - раскрыта по умолчанию: этап с первой неотмеченной операцией; если отмечено всё — ни одна.
- Содержимое этапа, сверху вниз: таймер (F-7), предупреждения (`warnings`, янтарная рамка и значок), схема (`scheme`), операции.
- Схема — моноширинный блок: строки `lines` без переносов, с горизонтальной прокруткой. Псевдографика `→ ↑ ↓ ←` не должна «разъезжаться».
- Операция — строка на всю ширину с чекбоксом, высота нажатия не меньше 48 dp. Нажатие в любом месте строки переключает отметку.
  - `id` операции мелким моноширинным текстом («9.5»);
  - для `type = "param"` — янтарная плашка со значением `param`;
  - у отмеченной операции текст приглушён и зачёркнут, справа время отметки `HH:mm`;
  - при отметке — короткий тактильный отклик (если вибрация включена в настройках).
- Меню `TopAppBar` (⋮):
  - **«Журнал остановки»** — открывает F-8;
  - **«Сбросить прогресс»** — диалог «Сбросить все отметки и таймеры? Перед сбросом можно сохранить журнал». Кнопки: «Отмена», «Сохранить журнал» (открывает «Поделиться», после возврата снова спрашивает), «Сбросить». Сброс удаляет отметки и таймеры, отменяет будильники и уведомления. История тренажёра **не** удаляется.
- Плавающая кнопка **«К текущему шагу»** прокручивает к первой неотмеченной операции и раскрывает её этап.
- Отметки сохраняются в БД сразу, без задержки. Приложение может быть убито в любой момент, и после этого ничего не теряется.

### F-3. Пошаговый режим (главная функция «помощника»)

Экран для работы на ходу: один шаг на экране, крупный текст, большие кнопки.

- Курсор движется по плоскому списку всех операций в порядке этапов. При открытии он стоит на первой неотмеченной операции (или на операции, переданной при переходе).
- Шапка: «Этап N из <всего этапов> · section», заголовок этапа, `condition` и бейдж «Критично», если есть. Ниже — «Шаг K из M» и общий прогресс.
- Центральная часть:
  - текст операции, не меньше 22 sp;
  - для `param` — крупная янтарная плашка со значением;
  - ID операции.
- Если у этапа есть `warnings`, над шагом показывается сворачиваемый блок предупреждений. На первом шаге этапа он раскрыт, на остальных свёрнут.

  - **«Выполнено»** — на всю ширину, высота не меньше 72 dp, цвет `cool`. Отмечает операцию с текущим временем и переводит курсор к следующей неотмеченной операции после текущей. Если таких после текущей нет, то к первой неотмеченной во всём списке.
  - **«◀ Назад» / «Вперёд ▶»** — сдвигают курсор на одну операцию без изменения отметок.
  - Если операция уже отмечена, вместо «Выполнено» — надпись «Выполнено в HH:mm» и кнопка **«Снять отметку»**.

### F-7. Таймеры этапов

Логика повторяет [`Timer.tsx`](https://github.com/Nodensss/OSTANOV/blob/main/components/ui/Timer.tsx), но таймер должен работать при свёрнутом и закрытом приложении и после перезагрузки телефона.

**Состояние** (таблица `timer_state`, ключ — `phaseId`): `startedAt: Long?` (момент последнего запуска, epoch ms, `null` на паузе), `elapsedMs: Long` (накопленное время до последней паузы), `finished: Boolean`, `firstStartedAt: Long?`, `finishedAt: Long?`.

**Чистые функции** в `domain/TimerMath.kt` (покрыть тестами):

- `durationMs = minutes × 60 000`;
- `running = startedAt != null && !finished`;
- `elapsed(now) = min(duration, elapsedMs + (running ? now − startedAt : 0))`;
- `remaining(now) = duration − elapsed(now)`;
- `start(now)`: `startedAt = now`; если `firstStartedAt == null`, то `firstStartedAt = now`. На завершённом таймере старт недоступен — сначала сброс;
- `pause(now)`: `elapsedMs += now − startedAt`, `startedAt = null`;
- `reset()`: всё в исходное состояние;
- `finish(now)`: `finished = true`, `elapsedMs = duration`, `startedAt = null`, `finishedAt = now`;
- формат отображения: меньше часа — `MM:SS` (`40:00`), час и больше — `H:MM:SS` (`3:00:00`). Секунды округляются вверх, как в вебе.

**Интерфейс таймера:**

- круговой индикатор прогресса (`cool` по `surface-2`), в центре оставшееся время;
- подпись `label` и «План: N мин»;
- кнопки «Запустить» / «Пауза» / «Продолжить» и «Сбросить» (сброс — с подтверждением, если таймер запущен или завершён);
- после завершения — красная пульсирующая рамка, текст «Время вышло» и время окончания `HH:mm`;
- тики обновления — раз в секунду, только пока экран виден.

**Работа в фоне:**

- При запуске или продолжении `AlarmManager` ставит будильник на момент `now + remaining`: `setExactAndAllowWhileIdle`, если `canScheduleExactAlarms()`, иначе `setAndAllowWhileIdle`. Пауза и сброс будильник отменяют.
- Пока таймер идёт, висит постоянное (ongoing) уведомление в канале «Таймеры (идут)» с низкой важностью и без звука. В нём «Этап N · label», обратный отсчёт системным хронометром (`setUsesChronometer(true)`, `setChronometerCountDown(true)`, `setWhen(endAt)`) и действие «Пауза». Для каждого таймера — отдельное уведомление.
- При срабатывании будильника `BroadcastReceiver` переводит таймер в `finished`, убирает уведомление об идущем таймере и показывает уведомление в канале «Таймеры (завершены)» с высокой важностью, звуком и вибрацией (вибрация — с учётом настроек). Текст по шаблону «Этап N · label — M мин истекли», например «Этап 9 · Циркуляция этилена через РБ — 40 мин истекли». Нажатие на уведомление открывает Чек-лист, прокрученный к этому этапу.
- Если приложение открыто в момент окончания: то же уведомление плюс звуковой сигнал и вибрация внутри приложения (если включены в настройках).
- При старте приложения и в `BOOT_COMPLETED` приложение проходит по всем запущенным таймерам: истёкшие переводит в `finished` (с уведомлением), для остальных заново ставит будильники и уведомления.
- Таймеры этапов 9 и 10 независимы и могут идти одновременно.
- Если нет разрешения на уведомления, таймер всё равно работает. В интерфейсе таймера показывается плашка «Уведомления выключены — сигнал об окончании не придёт» с кнопкой «Разрешить».

## Приложение Б. Эталон `.github/workflows/android.yml`

```yaml
name: Android APK

on:
  push:
    branches: [main]
    paths: ["android/**", "data/**", "scripts/check-android-content.py", ".github/workflows/android.yml"]
  pull_request:
    paths: ["android/**", "data/**", "scripts/check-android-content.py", ".github/workflows/android.yml"]
  workflow_dispatch:

permissions:
  contents: write

concurrency:
  group: android-${{ github.ref }}
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v4

      - name: Тексты алгоритма не захардкожены
        run: python3 scripts/check-android-content.py

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: "17"

      - uses: android-actions/setup-android@v3

      - uses: gradle/actions/setup-gradle@v4
        with:
          gradle-version: "8.11.1"

      - name: Ключ подписи (если заданы секреты)
        id: signing
        env:
          KEYSTORE_BASE64: ${{ secrets.ANDROID_KEYSTORE_BASE64 }}
        run: |
          if [ -n "$KEYSTORE_BASE64" ]; then
            echo "$KEYSTORE_BASE64" | base64 -d > "$RUNNER_TEMP/upe-stop.jks"
            echo "UPE_KEYSTORE_PATH=$RUNNER_TEMP/upe-stop.jks" >> "$GITHUB_ENV"
            echo "enabled=true" >> "$GITHUB_OUTPUT"
          else
            echo "enabled=false" >> "$GITHUB_OUTPUT"
          fi

      - name: Тесты, lint, debug-сборка
        working-directory: android
        run: gradle --no-daemon testDebugUnitTest lintDebug assembleDebug

      - name: Release-сборка
        if: steps.signing.outputs.enabled == 'true'
        working-directory: android
        env:
          UPE_KEYSTORE_PASSWORD: ${{ secrets.ANDROID_KEYSTORE_PASSWORD }}
          UPE_KEY_ALIAS: ${{ secrets.ANDROID_KEY_ALIAS }}
          UPE_KEY_PASSWORD: ${{ secrets.ANDROID_KEY_PASSWORD }}
        run: gradle --no-daemon assembleRelease

      - name: Подготовить APK
        id: apk
        run: |
          VERSION="0.1.${{ github.run_number }}"
          mkdir -p dist
          if [ "${{ steps.signing.outputs.enabled }}" = "true" ]; then
            cp android/app/build/outputs/apk/release/app-release.apk "dist/upe-stop-$VERSION.apk"
          else
            cp android/app/build/outputs/apk/debug/app-debug.apk "dist/upe-stop-$VERSION.apk"
          fi
          echo "version=$VERSION" >> "$GITHUB_OUTPUT"

      - uses: actions/upload-artifact@v4
        with:
          name: upe-stop-apk
          path: dist/*.apk
          retention-days: 30

      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: reports
          path: |
            android/app/build/reports/
            android/app/build/test-results/
          retention-days: 14

      - name: Релиз с APK
        if: github.ref == 'refs/heads/main' && github.event_name != 'pull_request'
        uses: softprops/action-gh-release@v2
        with:
          tag_name: android-v${{ steps.apk.outputs.version }}
          name: УПЭ Стоп для Android ${{ steps.apk.outputs.version }}
          target_commitish: ${{ github.sha }}
          files: dist/*.apk
          body: |
            Сборка из коммита ${{ github.sha }}.
            Установка: скачать APK на телефон и открыть. Подробности — android/README.md.
```
